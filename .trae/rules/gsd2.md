# GSD 2.0 & TDD 自动化协议

1. **读取任务池**：始终以 `specify/specs/` 目录为唯一事实来源，按文件名编号顺序（如 001, 002...）依次执行状态为 `[ ]` 的任务。
2. **TDD 强制循环**：
   - **红灯**：在编写功能代码前，必须先根据 Spec 的输入输出要求编写测试用例，并运行测试确认失败。
   - **绿灯**：编写最少量的代码使测试通过。
   - **重构**：优化代码，确保测试依然通过。
3. **自主接力（Automation）**：
   - 任务测试通过后，必须自动修改对应 Spec 文件，将状态标记为 `[x] Done`。
   - 自动在终端输出：“Task [编号] 已完成并验证，正在分析下一个任务...”。
   - 紧接着读取下一个 `[ ]` 任务，无需等待用户指令，直接开始测试编写。
4. **中断保护**：如果测试连续失败 3 次且无法自愈，必须停止自动化并向用户报告具体错误堆栈。
