# Feature Specification: WireGuard VPN Manager Service

**Feature Branch**: `001-vpn-manager-service`\
**Created**: 2026-04-17\
**Status**: Draft\
**Input**: User description: "云环境 WireGuard VPN 管理服务产品需求文档"

## System Overview

本系统（VPN Manager）用于管理云端局域网内虚拟机的WireGuard VPN配置。由于云平台只有一个公网地址，通过本系统控制新建虚拟机的对外VPN，使用户电脑能够与虚拟机建立VPN连接。

### System Scope

本次开发的系统包含三个组成部分：

| 组成部分     | 描述                                  |
| -------- | ----------------------------------- |
| **数据库**  | PostgreSQL数据库，存储资源池映射、VPN配置、归档记录等数据 |
| **后端逻辑** | API服务，处理虚拟机配置请求、前端应用查询请求、销毁请求等      |
| **管理前端** | Web管理界面，供Root管理员和普通管理员进行资源池管理和配置查看  |

### External Objects

本系统与以下外部对象进行交互（非本次开发范围）：

| 对象                      | 类型   | 描述                                   |
| ----------------------- | ---- | ------------------------------------ |
| **虚拟机 (VM)**            | 外部系统 | 运行在云端局域网内，首次启动时执行初始化脚本获取VPN配置        |
| **前端应用 (Frontend App)** | 外部系统 | 面向客户提供虚机租赁的业务平台，调用本系统API             |
| **用户电脑 (Client)**       | 外部对象 | 安装WireGuard客户端，导入配置文件与虚拟机建立跨公网的VPN连接 |

### Interaction Flow

```
用户电脑 <---> 前端应用 <---> 本系统 <---> 虚拟机
    |                                    |
    +-------- VPN连接 --------------------+
```

1. **资源池配置**：Root管理员通过本系统的管理前端，配置可用的公网UDP端口范围，并导入内网IP段。系统自动为每个内网IP分配公网UDP端口（私网IP:2588 ↔ 公网IP:随机UDP端口）。root管理员导出映射关系，让网络工程师配置到公网防火墙上。
2. **VM初始化**：虚拟机首次启动执行脚本，通过局域网访问本系统API获取WireGuard Server配置并启动服务
3. **配置生成**：本系统在VM初始化访问API时，在后端自动生成Server端和5个Client端秘钥，保存到数据库并返回Server配置给虚拟机。
4. **状态上报**：VM成功启动WireGuard后，通过API上报状态，后端更新数据库状态。
5. **配置查询**：外部前端应用通过API查询Client端配置，展示给其用户
6. **用户连接**：用户电脑安装WireGuard，导入从前端应用下载的配置文件，与虚拟机建立VPN连接
7. **资源销毁**：外部前端应用删除虚拟机时，通过API向本系统发起销毁请求。销毁时，被销毁虚拟机对应IP地址的数据，修改状态，从主表挪到数据库的归档表。

### Status Lifecycle

配置状态分为三个阶段：

| 状态                | 触发条件         | 说明                  |
| ----------------- | ------------ | ------------------- |
| **状态1 (init)**    | 数据库建立数据时     | VM首次请求配置，系统生成并保存配置  |
| **状态2 (started)** | 虚拟机返回配置完成后   | VM上报WireGuard启动成功   |
| **状态3 (deleted)** | 外部前端应用销毁虚拟机后 | 外部前端应用发起销毁请求，配置移入归档 |

## Clarifications

### Session 2026-04-17

- Q: 当配置处于状态1 (init)时，外部前端应用发起销毁请求，系统应如何处理？ → A: 正常执行销毁，状态改为状态3并移入归档表（与状态2销毁流程一致）。当VM上报启动完成时，如果查询不到状态1对应的记录，接口应返回报错信息"记录已销毁"
- Q: 资源池中IP映射的公网UDP端口是如何分配的？ → A: 系统自动从可用端口池中分配。Root管理员需先配置可用的公网UDP端口范围（如10000-20000），系统在导入内网IP时自动从该范围内随机分配端口，确保不冲突。
- Q: 当VM请求配置时，请求来源IP不在资源池映射中，系统应如何处理？ → A: 拒绝请求并返回明确错误"该IP未在资源池中配置"
- Q: 当Root管理员尝试删除正在使用中的IP映射时（该IP已有状态1或状态2的配置），系统应如何处理？ → A: 拒绝删除并提示"该IP存在活跃配置，请先销毁配置"
- Q: 当端口范围内所有端口都已分配完毕时，Root管理员尝试导入新IP，系统应如何处理？ → A: 拒绝导入并提示"端口范围已用尽，请先扩充端口范围"
- Q: 当VM上报就绪状态失败（脚本执行中断、网络故障等），导致配置停留在状态1无法转为状态2，系统应如何处理？ → A: 无需特殊处理。如果VM没有成功发送就绪上报请求，系统根本不知道该事件发生过。配置自然保持在状态1，等待VM后续重新上报。状态1的配置支持多次就绪上报（幂等性）。
- Q: 当客户端配置下载过程中网络中断，如何保证配置完整性？ → A: 配置文件可重复下载，网络中断后用户重新下载即可。配置文件是静态生成的，存储在数据库中，不会因下载失败而丢失。
- Q: 系统是否需要记录操作日志以支持审计和故障排查？ → A: 记录详细日志（包含所有API请求和响应），保留3个月内的所有日志供反查。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - VM初始化获取VPN配置 (Priority: P1)

作为虚拟机（外部系统），在首次启动时需要自动获取WireGuard VPN配置并启动服务。

**Why this priority**: 这是系统最核心的功能，没有它后续所有VPN连接都无法建立。VM必须能够自动获取配置才能让运维人员远程访问。

**Independent Test**: 可以通过模拟VM请求配置API，验证返回正确的Server端配置，并确认WireGuard服务能够成功启动。

**Acceptance Scenarios**:

1. **Given** VM实际请求的IP地址，资源池中存在该IP的映射记录，**When** VM通过内网API请求配置，，**Then** 系统生成Server端和5个Client端秘钥，保存配置，返回Server端配置，状态设为状态1
2. **Given** VM已获取配置且状态为状态1，**When** VM因网络抖动重复请求配置，**Then** 系统返回相同的配置（幂等性保证）
3. **Given** VM成功启动WireGuard，**When** VM调用就绪API上报状态，**Then** 系统将状态更新为状态2
4. **Given** VM状态为状态2，**When** VM再次请求配置，**Then** 系统拒绝请求并返回错误信息
5. **Given** VM尝试上报就绪状态，**When** 配置已被销毁（主表中不存在该IP的状态1记录），**Then** 系统返回错误信息"记录已销毁"

***

### User Story 2 - 外部前端应用查询客户端配置 (Priority: P1)

作为外部前端应用，需要通过API查询客户端配置以展示给其用户。

**Why this priority**: 这是用户接入VPN的必要步骤，与US1同等重要，两者共同构成核心MVP。

**Independent Test**: 可以通过模拟外部前端应用API请求，查询指定IP的客户端配置，验证返回5个有效配置。

**Acceptance Scenarios**:

1. **Given** 外部前端应用已认证，**When** 查询指定IP的客户端配置，**Then** 系统返回5个客户端配置JSON（含备注名）
2. **Given** 指定IP不存在活跃配置或状态为状态3，**When** 查询配置，**Then** 系统返回空结果或提示信息

***

### User Story 3 - Root管理员管理资源池 (Priority: P2)

作为Root管理员，需要在本系统的管理前端中配置端口范围、导入内网IP段，系统自动生成映射关系，并导出供网络工程师配置防火墙。

Root管理员有权删除或修改已有映射关系。

**Why this priority**: 资源池管理是系统运行的前置条件，但可以在系统部署后一次性配置完成。

**Independent Test**: 可以通过Root用户登录本系统管理前端，配置端口范围，批量导入IP映射，验证数据正确存入数据库并显示在资源池列表中，并能成功导出映射关系。管理员可以删除或修改已有映射关系。

**Acceptance Scenarios**:

1. **Given** Root用户已登录本系统管理前端，**When** 配置公网UDP端口范围（如10000-20000），**Then** 系统保存端口范围配置，后续IP导入时从该范围自动分配端口
2. **Given** Root用户已登录本系统管理前端且已配置端口范围，**When** 批量导入IP段映射，**Then** 系统自动校验IP地址前两位一致性，为每个IP自动分配可用端口并存入资源池。如果系统初始化，系统中无任何记录时，可以不进行校验。
3. **Given** 导入的IP段存在B类地址不一致，**When** 提交导入，**Then** 系统拒绝导入并提示错误信息
4. **Given** 资源池中存在映射记录，**When** Root用户查看资源池，**Then** 显示所有映射记录
5. **Given** Root用户需要修改映射，**When** 编辑映射信息，**Then** 系统更新记录并记录修改时间
6. **Given** Root用户需要删除映射，**When** 删除映射信息，**Then** 系统更新记录并记录删除时间
7. **Given** 资源池中存在映射记录，**When** Root用户导出映射关系，**Then** 系统生成映射关系文件供网络工程师配置防火墙

***

### User Story 4 - 外部前端应用销毁配置 (Priority: P2)

作为外部前端应用，需要在删除虚拟机时通过API向本系统发起销毁请求。

**Why this priority**: 资源回收是系统长期运行的重要功能，但不影响核心VPN连接功能。

**Independent Test**: 可以通过模拟外部前端应用API请求，发起销毁请求，验证配置移入归档表，状态更新为状态3。

**Acceptance Scenarios**:

1. **Given** 存在活跃配置（状态1或状态2），**When** 外部前端应用发起销毁请求，**Then** 系统将配置状态改为状态3并从主表移入归档表
2. **Given** 配置已销毁（状态为状态3），**When** 外部前端应用查询该IP的配置，**Then** 返回空结果及提示信息
3. **Given** 配置已销毁，**When** 查看历史记录，**Then** 可以在归档表中查看该IP的历史配置

***

### User Story 5 - 管理员查看配置 (Priority: P2)

作为本系统的管理员（Root或普通管理员），需要在管理前端中查看VPN配置信息。

**Why this priority**: 管理员需要查看配置以进行运维管理，但不影响核心VPN连接功能。

**Independent Test**: 可以通过管理员登录本系统管理前端，查看配置详情，验证Root用户可看明文，验证Root用户可下载server端和client端配置；普通管理员看到脱敏，普通管理员只可以下载client端配置。

**Acceptance Scenarios**:

1. **Given** Root用户已登录管理前端，**When** 查看配置详情，**Then** 显示完整秘钥明文并可下载配置文件
2. **Given** 普通管理员已登录管理前端，**When** 查看配置详情，**Then** 秘钥字段显示为星号脱敏，仅可下载client端配置
3. **Given** 指定IP存在历史归档记录，**When** 点击"查看历史"按钮，**Then** 弹窗展示该IP的所有历史配置
4. **Given** 指定IP无历史记录，**When** 点击"查看历史"按钮，**Then** 显示"无历史记录"提示
5. **Given** 查询配置或历史记录，**When** 支持根据IP地址或时间段过滤，**Then** 显示符合查询条件的记录

***

## Requirements *(mandatory)*

### Functional Requirements

**资源池管理（管理前端）**

- **FR-001**: 系统必须支持Root管理员配置公网UDP端口范围（起始端口-结束端口）
- **FR-002**: 系统必须支持Root管理员通过管理前端导入内网IP段
- **FR-003**: 系统必须在导入IP时自动从配置的端口范围内随机分配可用端口，确保端口不冲突
- **FR-004**: 当端口范围内所有端口都已分配完毕时，系统必须拒绝导入并提示"端口范围已用尽，请先扩充端口范围"
- **FR-005**: 系统必须自动校验批量导入IP段的B类地址一致性（前两位相同）；系统初始化时（无任何记录）可跳过校验
- **FR-006**: 系统必须维护资源池映射记录，支持Root管理员修改映射信息
- **FR-007**: 系统必须支持Root管理员删除映射关系，并记录删除时间
- **FR-008**: 当删除的IP映射存在活跃配置（状态1或状态2）时，系统必须拒绝删除并提示"该IP存在活跃配置，请先销毁配置"
- **FR-009**: 系统必须支持Root管理员导出映射关系，供网络工程师配置防火墙

**VM配置获取（后端API）**

- **FR-010**: 系统必须提供VM端API供虚拟机获取WireGuard Server配置
- **FR-011**: 系统必须从TCP报文头RemoteAddr提取请求来源IP，禁止从JSON Body读取
- **FR-012**: 当请求来源IP不在资源池映射中时，系统必须拒绝请求并返回错误"该IP未在资源池中配置"
- **FR-013**: 系统必须保证配置获取的幂等性（相同IP返回相同配置）
- **FR-014**: 系统必须在VM首次请求配置时，在后端自动生成Server端和5个Client端秘钥对
- **FR-015**: 系统必须将生成的配置保存到数据库，状态设为状态1
- **FR-016**: 当VM上报就绪状态时，如果主表中不存在该IP的状态1记录，系统必须返回错误信息"记录已销毁"

**VPN网段映射（后端逻辑）**

- **FR-017**: 系统必须根据VM内网IP自动计算VPN网段（A.B.C.D → 10.C.D.0/24）
- **FR-018**: 系统必须为VM分配固定IP（10.C.D.254）
- **FR-019**: 系统必须为客户端分配IP范围（10.C.D.1至10.C.D.5）

**配置模板（后端逻辑）**

- **FR-020**: Server端配置必须包含PostUp和PostDown的iptables NAT转发规则
- **FR-021**: Client端配置必须包含PersistentKeepalive = 25设置

**状态管理（后端逻辑）**

- **FR-022**: 系统必须支持配置状态流转：状态1 → 状态2 → 状态3
- **FR-023**: 系统必须在VM上报就绪后将状态更新为状态2
- **FR-024**: 状态1的配置必须支持多次就绪上报（幂等性），VM可因网络问题重复上报
- **FR-025**: 系统必须在状态2后拒绝后续配置请求
- **FR-026**: 系统必须将状态3的记录从主表移入归档表
- **FR-027**: 系统必须允许销毁状态1的配置（与状态2销毁流程一致）

**外部前端应用接口（后端API）**

- **FR-028**: 系统必须提供API供外部前端应用查询指定IP的客户端配置
- **FR-029**: 系统必须提供API供外部前端应用发起销毁请求，支持销毁状态1和状态2的配置

**管理前端功能**

- **FR-030**: 管理前端必须支持Root用户查看完整秘钥明文并下载Server端和Client端配置文件
- **FR-031**: 管理前端必须对普通管理员的秘钥字段进行星号脱敏显示
- **FR-032**: 普通管理员仅可下载Client端配置，不可下载Server端配置
- **FR-033**: 配置文件必须支持重复下载，网络中断后用户可重新下载
- **FR-034**: 管理前端必须支持查看历史配置记录
- **FR-035**: 管理前端必须支持根据IP地址或时间段过滤查询配置和历史记录

**安全性**

- **FR-036**: 所有API必须使用HTTPS加密
- **FR-037**: VM端API必须使用固化Token + 来源IP双重校验
- **FR-038**: 外部前端应用API必须使用认证Token
- **FR-039**: 管理前端必须实现用户认证和权限控制

**可观测性**

- **FR-040**: 系统必须记录所有API请求和响应的详细日志
- **FR-041**: 日志必须包含请求时间、来源IP、请求路径、请求参数、响应状态码、响应时间等信息
- **FR-042**: 日志必须保留3个月，超过3个月的日志可自动清理
- **FR-043**: 日志必须支持按时间范围、IP地址、请求类型等条件查询

### Key Entities

- **端口范围配置 (PortRange)**: 公网UDP端口范围配置，包含起始端口和结束端口
- **资源池映射 (ResourcePool)**: 内网IP与公网端口的映射关系（私网IP:2588 ↔ 公网IP:分配的UDP端口），包含创建时间、修改时间、删除时间
- **VPN配置 (VpnConfig)**: 主表，存储状态1和状态2的VPN配置记录，包含：
  - 虚拟机IP地址
  - Server端配置文件
  - 5个Client端配置文件
  - 状态（状态1/状态2）
  - 创建时间、状态转变时间
- **归档配置 (VpnArchive)**: 存储状态3的VPN配置历史记录，包含删除时间
- **用户角色 (UserRole)**: 本系统管理前端的用户角色：
  - **Root管理员**：全权限，可查看明文秘钥，可下载Server端和Client端配置
  - **普通管理员**：秘钥脱敏显示，仅可下载Client端配置
- **操作日志 (OperationLog)**: 记录所有API请求和响应，包含：
  - 请求时间、来源IP、请求路径、请求参数
  - 响应状态码、响应时间
  - 日志保留期限：3个月

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: VM从请求配置到WireGuard服务启动完成时间不超过30秒
- **SC-002**: Root用户从管理前端登录到下载客户端配置完成时间不超过1分钟
- **SC-003**: 系统支持至少100个并发VM配置请求
- **SC-004**: 配置获取API幂等性保证100%（相同IP重复请求返回相同配置）
- **SC-005**: 秘钥脱敏功能100%覆盖普通管理员可见的所有秘钥字段
- **SC-006**: 销毁后配置状态100%正确更新为状态3并从主表移入归档表
- **SC-007**: 所有API响应时间P95低于200ms
- **SC-008**: 系统可用性达到99.9%
- **SC-009**: 端口分配冲突率0%（同一端口不会被分配给多个IP）

## Assumptions

- 所有虚拟机的内网IP属于同一个B类网段（前两位一致）
- Root管理员配置的端口范围足够容纳所有需要映射的内网IP数量
- Root管理员导出映射关系后，网络工程师会配置防火墙端口映射
- 虚拟机已安装WireGuard软件包
- 用户电脑已手动安装WireGuard客户端
- 数据库使用PostgreSQL
- 系统部署在云环境内网，VM可通过内网IP访问本系统API
- VM初始化脚本具有执行权限并能够访问内网API
- Root管理员和普通管理员的权限体系已预先定义
- 本系统与外部前端应用之间的认证机制已建立
